# Generate Architecture Documentation

Generate or update Mermaid-in-Markdown architecture diagrams based on the current codebase state.

**Scope:** `$ARGUMENTS` (defaults to `all` if empty)

Valid scopes: `all`, `erd`, `routes`, `modules`, `auth`, `overview`

## Output Directory

All files go to `docs/architecture/`. Create the directory if it doesn't exist.

## Instructions

For each scope below (or all if scope is `all` or empty), read the specified source files, then write the corresponding Mermaid diagram file. Overwrite existing files — the skill is idempotent.

After generating individual diagrams, always regenerate `docs/architecture/README.md` as an index.

---

### Scope: `erd` → `docs/architecture/erd.md`

Read `zenstack/schema.zmodel`.

Generate a Mermaid `erDiagram` covering:
- All models with key fields (id, foreign keys, enum fields, important domain fields)
- Relationship cardinality using proper erDiagram syntax (||--o{, ||--||, etc.)
- Group models by domain in comments

Format:
```markdown
# Entity Relationship Diagram

> Auto-generated by `/generate-docs erd`. Do not edit manually.

Last updated: YYYY-MM-DD

## Data Model

\`\`\`mermaid
erDiagram
    %% Core
    User { ... }
    ...
\`\`\`

## Notes
- Describe key design decisions (e.g., auth schema separation, soft deletes, enum usage)
```

### README Index → `docs/architecture/README.md`

Always regenerate this file last. It should link to all diagram files with brief descriptions:

```markdown
> Auto-generated by `/generate-docs`. Do not edit manually.

Last updated: YYYY-MM-DD

| Diagram | File | Description |
|---------|------|-------------|
| Entity Relationship | [erd.md](erd.md) | Data model: all ZenStack models, fields, relationships |
| Routes | [routes.md](routes.md) | Application route tree: pages, layouts, API endpoints |
| Modules | [modules.md](modules.md) | Module dependency graph: src/lib and src/components |
| Auth Flow | [auth-flow.md](auth-flow.md) | Authentication: sign-up, provisioning, session, policies |

## Regeneration

Run `/generate-docs` to regenerate all diagrams, or `/generate-docs <scope>` for a specific one.
```

## Quality Checks

Before finishing:
1. Verify every Mermaid block has valid syntax (matching opening/closing, proper node IDs, no special chars that break rendering)
2. Ensure diagrams reflect the CURRENT codebase state, not assumptions
3. Use consistent node naming across diagrams (e.g., same model names as in schema.zmodel)
